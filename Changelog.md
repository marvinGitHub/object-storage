# Changelog

All notable changes to this project will be documented in this file. From 1.0 on the project follows [Semantic Versioning](https://semver.org), see [Versioning and stability](Readme.md#versioning-and-stability). Changes of experimental features (OQL) that break existing usage are listed under **Breaking (experimental)** and may come with a minor release.

## [Unreleased]

## [1.0.0-rc.5] - 2026-11-09

The fifth release candidate of 1.0: `UPDATE` in OQL writes into lists and maps with paths (`SET newlist['today'] = NOW()`, `tags[]`, `friends.*.active`) and removes keys and elements with `REMOVE`. Nothing has to be migrated, see [UPGRADE.md](UPGRADE.md#from-100-rc4-to-100-rc5).

### Added
- OQL *(experimental)*: paths in `UPDATE` (`docs/query.md`, "INSERT, UPDATE, DELETE and ALTER"). `SET` writes keys and elements of the lists and maps (arrays) an object holds, as in PHP: `UPDATE stdClass SET newlist['today'] = NOW()` (missing lists and maps on the way are created), `tags[0]`, `tags[-1]` (from the end, must exist), `tags[6]` (beyond the end: the list becomes a map), `tags[]` (appended), `settings.mail.enabled`, `friends.*.active` (in every element). `UPDATE … REMOVE path, …` takes keys and elements out (positions as before removing; lists are numbered anew, maps keep their keys), also with `SET`: `UPDATE Class SET a = 1 REMOVE b['x'] WHERE …`. Paths into referenced objects and dates are refused, as are two targets that may name the same value. Dates and `REF()` may be written into lists and maps. `REMOVE` isn't reserved. `OqlUpdatePathTest`; an example in [OQL by example](docs/examples/oql-by-example.md#writing-insert-update-delete).

## [1.0.0-rc.4] - 2026-11-09

The fourth release candidate of 1.0: faster reflection when loading, storing and writing with OQL. **Read [UPGRADE.md](UPGRADE.md#from-100-rc3-to-100-rc4) before upgrading.**

### Added
- `Reflection::acceptsObject(ReflectionType $type, string $class)` — whether a declared type accepts an object of a class (used by OQL `REF()`), `Reflection::acceptsLazyReference(?ReflectionType $type)` — whether a declared type can hold a `LazyLoadReference`, and `Reflection::getClassProperty($class, $property)` — a declared property, cached per class.

### Changed
- Performance: `Reflection::getProperty()` takes declared properties from a cache per class instead of creating a `ReflectionObject` for every object; a `ReflectionObject` is only created for dynamic properties. `Reflection::allowsDynamicProperties()`, `acceptsObject()` and `acceptsLazyReference()` cache their results. OQL writes (`INSERT`, `UPDATE`, `ALTER … DROP ATTRIBUTE`), the graph visitor and the CLI command `put` use the cached `ReflectionClass` and properties.
- `ObjectStorage::supportsLazyReference()` and the migration `AttributeToReference` use `Reflection::acceptsLazyReference()`; the two checks were the same. **Breaking** for subclasses of `ObjectStorage` only: the protected property `$lazyloadReferenceSupportCache` is removed.
- OQL *(experimental)*: `INSERT` and `UPDATE` also accept properties not declared by a class whose parent class has `#[AllowDynamicProperties]` (inherited as in PHP); only the class itself was checked before.

## [1.0.0-rc.3] - 2026-11-09

The third release candidate of 1.0: paths into lists and keys, when objects were modified (`touch()`), and much more of OQL — search indexes for numbers, dates and booleans, `REGEXP`, math, `CONCAT`, `DATE_SUB`, `ALTER … DROP ATTRIBUTE` — taught by the new [OQL by example](docs/examples/oql-by-example.md). **Read [UPGRADE.md](UPGRADE.md#from-100-rc2-to-100-rc3) before upgrading.**

### Added
- Paths into lists and keys (`docs/search.md`, "Paths into lists and keys"), the same for search indexes, unique indexes and OQL, also across referenced objects: `friends.*.name` / `friends[*].name` (all elements), `friends[0].name`, `friends[-1].name` (by position), `friends['alex'].name` (by key, also keys with dots), `friends.*.friends.*.name`. `melia\ObjectStorage\Path\Path` parses and writes them (`PathSegment`, `InvalidPathException`); `Field::getPathSegments()` and `DocumentBuilder::extract()` take its segments. Suggested fields write keys that aren't plain names in brackets.
- OQL *(experimental)*: the same paths in columns; a condition comparing a path with `*` directly is true if it is true for any element (`WHERE u.friends.*.name = 'Alex'`), negated for none; `JOIN … ON f = u.friends.*`; a search index field of a list of strings with the same path answers `=`/`IN` on a path with `*`.
- When objects were modified (`docs/getting-started.md`, "When an object was created and modified"): the metadata records `timestampModification`, set by every write of the data (`store()` of a changed object, OQL `INSERT`, `UPDATE`, `ALTER … DROP ATTRIBUTE`), not by lifetime changes. `ObjectStorage::touch($uuid, ?DateTimeInterface $at)` sets it without changing the data, revision or lifetime (only the metadata is written; event `TOUCHED`), also on the CLI (`touch <uuid> [--at …]`) and in the viewer (**Touch** on the page of a record, which shows created, modified and the revision). `getCreatedAt()`, `getModifiedAt()`, `Metadata::getTimestampModification()` (the creation time for metadata written before).
- OQL *(experimental)*: `CREATED(alias)` and `MODIFIED(alias)` (without alias: of the only source) give the timestamps of the metadata as dates.
- OQL *(experimental)*: `ALTER CLASS Class DROP ATTRIBUTE property [, DROP ATTRIBUTE …]` removes properties from the stored objects of a class, with `ALTER TABLE Class DROP [COLUMN] property` as the same for SQL (`docs/query.md`, "INSERT, UPDATE, DELETE and ALTER"). Written like `UPDATE`, also as a dry run; properties the class still declares are refused. The words aren't reserved. The CLI, the viewer (asks before running, POST only) and `Oql::writes()` treat it as a write.
- OQL *(experimental)*: search indexes for numbers, dates and booleans (`docs/query.md`, "Indexes"). Besides `=`/`IN` on string fields, a Loupe search index now answers `=`, `IN`, `<`, `<=`, `>`, `>=` and `BETWEEN` with numbers on `NUMBER` fields, with dates or texts that are dates on `DATE` fields, and `= TRUE`/`= FALSE` on `BOOLEAN` fields, also with the value on the left (`10 < price`); the filter also names the objects whose value the field couldn't convert (`OR field IS NULL`), so results stay those without indexes. Assumed: number fields hold numbers and date fields dates (a date in a number field, or a number in a date field, compares otherwise in OQL). `OqlSearchAccessTest` compares the rows with and without indexes on values of mixed types. The "Planned" note is gone.
- OQL *(experimental)*: `[NOT] REGEXP pattern` — a regular expression (PCRE, Unicode) matching anywhere in the value, minding case unless `(?i)`; also on paths with `*` (any element); `REGEXP_SUBSTR(text, pattern)` and `REGEXP_REPLACE(text, pattern, replacement)`. Patterns written in the query are checked before running. Highlighted in the query console.
- OQL *(experimental)*: `CONCAT(a, b, …)` and `CONCAT_WS(separator, a, b, …)` join texts, leaving `NULL` out (as in PostgreSQL and SQLite; `||` stays `NULL` with a `NULL`); `DATE_SUB(date, amount, unit)`, the same as `DATE_ADD` with the amount negated. Highlighted in the query console.
- OQL *(experimental)*: math as in MySQL — operators `%` and `DIV`; `CEIL`/`CEILING`, `FLOOR`, `TRUNCATE`, `MOD`, `SIGN`, `POW`/`POWER`, `SQRT`, `EXP`, `LN`, `LOG` (also with a base), `LOG10`, `LOG2`, `PI`, `RAND`, `SIN`, `COS`, `TAN`, `COT`, `ASIN`, `ACOS`, `ATAN`, `ATAN2`, `DEGREES`, `RADIANS`, `CRC32`, `CONV` (`docs/query.md`, "Math"). Results that aren't numbers are `NULL`. `DIV` isn't reserved.
- Documentation: [OQL by example](docs/examples/oql-by-example.md), the query language step by step on a small shop — conditions, `NULL`, computed values, paths, joins (also over the elements of lists), lists and keys, grouping, dates and `NOW()`, `INSERT`/`UPDATE`/`DELETE`, adding a date property and filling it, renaming and dropping properties, `EXPLAIN`, the CLI, and a comparison with SQL. `OqlByExampleTest` runs every SQL block of the page and compares the results shown (`OQL_EXAMPLES_UPDATE=1` writes them).

### Changed
- **Breaking:** in paths of fields and unique indexes, `[`, `]` and a segment that is exactly `*` are syntax now; a key containing them is written in brackets: `['a[1]']`.
- The creation time of an object (`timestampCreation`) stays the time of its first `store()` (see Fixed); it was the time of the last write before.

### Breaking (experimental)
- OQL: `REGEXP` is a keyword: a property named so is written in backticks (`` `regexp` ``). `%` is an operator.

### Fixed
- `timestampCreation` in the metadata was set to the time of every write; it now stays the time of the first `store()`.

## [1.0.0-rc.2] - 2026-11-09

The second release candidate of 1.0: dates are stored inline and can be filtered and sorted in OQL, search indexes and the viewer. **Read [UPGRADE.md](UPGRADE.md#from-100-rc1-to-100-rc2) before upgrading.**

### Added
- OQL: dates (`docs/query.md`, "Dates"). Dates stored inline are values compared, sorted (`ORDER BY`, `MIN`, `MAX`), grouped and made distinct by their point in time across time zones; texts compared with a date are read as dates in the form of ISO 8601 (`'2026-01-01'`, `'2026-01-01 10:00'`, `'…T10:00:00.5Z'`, `'…+01:00'`), in UTC without offset; texts that aren't dates are compared with the date as text, as in SQLite. Results give a date as its point in time in UTC as stored. Functions `NOW()` (the same for a statement), `DATETIME(x [, zone])`, `DATE(x [, zone])`, `YEAR`, `MONTH`, `DAY`, `HOUR`, `MINUTE`, `SECOND(x [, zone])` (UTC unless a zone is given) and `DATE_ADD(x, amount, unit)` (in the time zone of the date). Parameters may be `DateTimeInterface`. `INSERT` and `UPDATE` write dates into properties declared as dates (from dates or texts, in the declared class) and into properties without type; indexes aren't used for texts that are dates. `OqlSqliteTest` compares dates in several time zones, written in several forms, with SQLite (as text in UTC, `strftime()`, `date()`). The query console highlights the new functions.

- Viewer: dates of a record are edited with date widgets (`docs/maintenance.md`, "The web viewer"): date and time in the time zone of the date, the time zone chosen from those of the browser (or an offset, or the abbreviation it has), written into the JSON as stored, replacing only that date. The widgets follow the JSON typed; **Cancel** now also drops the changes of the JSON. `assets/date-fields.js` (tested with Node, also across daylight saving time as PHP resolves gaps and overlaps) and a Playwright test with a seeded appointment.
- Search indexes: date fields (`docs/search.md`, "Types"). `FieldType::DATE` and `DATE_ARRAY` index dates stored inline, texts that are dates and numbers as the seconds since 1970-01-01 UTC; a date is one value, also in lists and through references (`DocumentBuilder::extract()` doesn't split it into its parts, `DocumentBuilder::dates()`); `STRING` fields give dates as their point in time in UTC, `NUMBER` fields as seconds. Fields of dates are suggested as `DATE` (sortable) and `DATE_ARRAY`. Loupe: texts that are dates compared with date fields are written as numbers (`Loupe\FilterDates`: comparisons, `IN`, `BETWEEN`, before 1970 too), hits return dates as their point in time in UTC. `FieldType::isList()`, `isNumeric()`. The query builder of the viewer offers the operators of dates, checks the values (also the order of `BETWEEN` by the point in time) and reads date filters back. Date texts are parsed in one place, `Serialization\DateTimeValue::parse()`, for OQL and the search indexes.

### Changed
- **Dates are stored inline** (`docs/serialization.md`, "Dates"): instances of `DateTimeInterface` are values of the object holding them, `{"__datetime": "<UTC with microseconds>", "tz": "<time zone>", "class": "<class>"}`, instead of records of their own with a reference. A date is restored exactly (point in time, time zone, class; `DateTime`, `DateTimeImmutable` and subclasses), also in arrays, untyped properties and the data of `__unserialize()`; a declared type of the property converts it (`DateTime` ↔ `DateTimeImmutable`). The point in time in UTC sorts as text in the order of time, the base for filtering and sorting dates in OQL and search indexes. The key is reserved per object like `__reference` (`Metadata::getReservedDateTimeName()`, `reservedDateTimeName` in the metadata). The reserved names live in `Metadata\ReservedNamesTrait`, by kind (`getReservedName()`, `setReservedName()`, `getReservedNames()`, `reserveNamesAvoiding()`, `chooseReservedNames()`), stored as `reserved<Kind>Name`; a further kind is one entry in `RESERVED_NAME_DEFAULTS`. An unknown class or time zone is loaded as `DateTimeImmutable` or in UTC and logged (`DateTimeRestorationFailureException`). Dates stored as records of their own still load, and are stored inline when the object holding them is stored again (see UPGRADE.md).

## [1.0.0-rc.1] - 2026-11-06

The first release candidate of 1.0. It contains all changes since 0.0.4: the tags 0.0.5 to 0.0.10 were published without sections of their own in this file, their changes are listed here. **Read [UPGRADE.md](UPGRADE.md) before upgrading**, several changes are breaking.

### Highlights
- **Unique indexes**: values no two objects of a class may share, like a UNIQUE constraint, safe across processes (`docs/unique.md`).
- **Search indexes**: full-text search, filters, sorting and facets with exchangeable engines, Loupe included, with joins into referenced objects (`docs/search.md`).
- **OQL** *(experimental)*: an SQL-like query language with joins, paths into referenced objects, `GROUP BY`, and `INSERT`/`UPDATE`/`DELETE`, using the indexes, in code, the CLI and the viewer (`docs/query.md`).
- **Durability and concurrency**: crash-safe writes with `fsync`, revisions and optimistic locking, locks based on symfony/lock, safe mode that keeps the storage readable.
- **Tooling**: named configurations, copying and moving between storages, stepped maintenance with progress, and a reworked viewer.
- **Requirements**: PHP 8.5 and Symfony 8.

### Added
- OQL (`melia\ObjectStorage\Query`, see `docs/query.md`): a query language like SQL for the objects of a storage, read as stored (the classes aren't needed). `SELECT [DISTINCT]` with expressions, `*` and `alias.*`; `FROM` classes by short or full name; `[INNER] JOIN` and `LEFT JOIN` with any condition (equalities by hashing); paths into referenced objects (`p.category.parent.title`), the alias alone as the UUID of the object (`JOIN Category c ON c = p.category`); `WHERE` with comparisons, `IS NULL`, `IN`, `BETWEEN`, `LIKE` (ignoring case, backslash escapes), arithmetic, `||`, `LOWER`, `UPPER`, `LENGTH`, `TRIM`, `SUBSTR`, `ABS`, `ROUND`, `COALESCE`, `IFNULL`; `GROUP BY` with `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` (also `DISTINCT`), `HAVING`; `ORDER BY` by expressions, names and positions; `LIMIT`, `OFFSET`; parameters (`?`, `:name`). SQL semantics: three-valued logic with `NULL`, `NULL` first when sorting ascending; numbers written as text are compared with numbers as numbers (as in MySQL). Errors name line and column (`QueryException`). `Oql::query()` returns a `Result` (columns, rows, rows by name). Tested against SQLite with random data and queries (`OqlSqliteTest`). CLI command `query` (table or `--json`, `--file`, `--param`); in the viewer a query console (**Query**: Ctrl+Enter, results linking UUIDs to the records, errors, a history in the browser), tested with Playwright. The keyword `UUID` is the UUID of an object (`WHERE UUID = ?`, `p.UUID`, `p.category.UUID`), anywhere a value can be. `INSERT INTO … VALUES`, `UPDATE … SET … WHERE` and `DELETE FROM … WHERE` write the data as stored (`writeRaw()`, so referenced objects aren't written along), with references by `REF(uuid)`; values are checked against the types of the class if it can be loaded, `INSERT` sets defaults (also of promoted constructor parameters); all values are checked before the first write, each object is written under its exclusive lock after checking its condition again; unique indexes are checked and search indexes follow; a dry run (`query(…, dryRun: true)`, `--dry-run`, **Dry run** in the viewer) writes nothing. In the viewer, writing statements ask first and run by POST only. The query console highlights the syntax of OQL as it is typed (`assets/oql-highlight.js`, tested with Node and Playwright) and underlines the position of an error in the query. Writes are tested against SQLite too. Queries stream: objects are read one after another and only what the query uses is kept (early stop with `LIMIT`, a heap for `ORDER BY … LIMIT`, running aggregates per group), so 100,000 objects fit in 128 MB; `query(…, maxRows:)` with `Result::$truncated`. Indexes find the objects for `UUID = / IN`, for `=`/`IN` on the path of a unique index, and on filterable string fields of an up-to-date Loupe search index (`new Oql($storage, $searchManager, $uniqueManager)`), only where they name every matching object; `EXPLAIN SELECT …` shows the access per source. Unique indexes: `Manager::isComplete()` is false while `create()` or `rebuild()` claims the values (or after an interruption), queries don't use such an index.
- `InMemoryCache` takes `maxEntries` and drops the least recently used entries; the default caches of `ObjectStorage` and configurations of type `memory` are bounded to `InMemoryCache::DEFAULT_MAX_ENTRIES` (10,000), so reading many objects no longer fills the memory.
- Search indexes: paths lead into referenced objects, a join when indexing (see `docs/search.md`, "Joins"): `category.title` indexes the title of the referenced category, `labels.title` those of all referenced labels, `category.parent.title` follows two references (at most three, `DocumentBuilder::MAX_REFERENCES_PER_PATH`); nested objects such as an address are reached the same way. Documents record the referenced objects they were built from in the reserved attribute `referencedUuids`, the state the classes of those objects (`State::$joinedClasses`, `IndexInterface::getJoinedClasses()`). With the manager attached, storing or deleting a referenced object records it (`IndexInterface::recordReferenceChange()`), and the sync updates the documents built from it, also those of a running build; auto sync applies at most `Manager::AUTO_SYNC_MAX_CHANGES` (1,000) changes after a store, the others stay pending for the next sync. Engines implement `EngineIndexInterface::referencing()`; the index asks again by longer UUID prefixes when an engine returns its limit, so any number of dependent documents is found. `DocumentBuilder::suggestFields()` takes a reader of referenced objects and suggests their values too, `suggestFieldsFrom()` merges the suggestions of several objects (a value missing in one is taken from the others). The viewer suggests fields from up to 20 objects, e.g. `category.title`, and offers the indexes joining the class of a record when saving it (marked "joined"). Indexes built before have to be rebuilt to follow changes of referenced objects. The Doctrine example indexes the name of the customer with each order.
- Unique indexes (`melia\ObjectStorage\Unique`, see `docs/unique.md`): values no two objects of a class may share, like a UNIQUE constraint — single values or combinations of paths into the stored data, optionally case-insensitive; null values aren't unique, as in SQL. `Manager::attach()` checks every `store()` and `writeRaw()` (copies, moves) under the lock of the object, and releases the values of deleted objects; a violation throws a `UniqueConstraintViolationException` naming the object having the values, and nothing is written. Safe across processes: the claim of a value stays locked until the object is written. `find()` and `findOwner()` look objects up by their values; `create()` claims the values of the objects stored before and fails with a `DuplicateValuesException` listing duplicates; `rebuild()`, `drop()`. Claims left by a crash are recognized and taken over. In the viewer: **Unique indexes** (create, rebuild, drop), checked when editing and duplicating records; the form of a search index has a **Unique** flag (and **ignore case**) per field, creating or dropping the unique index on its path (`Unique\PathIndexes`; saving fails and nothing is saved if stored objects share a value). CLI: `unique:list`, `unique:create`, `unique:rebuild`, `unique:drop`, `unique:find`; all commands writing objects check the unique indexes of the storage (and of the target of `copy`/`move`). A storage without unique indexes gets no directory for them.
- Constraints (`Constraint\ConstraintInterface`, `ObjectStorage::addConstraint()`, `checkConstraints()`): rules every written object has to satisfy, checked before the data of an object is written; `ConstraintViolationException`, event `CONSTRAINT_VIOLATION`.
- Example "Coming from Doctrine ORM" (`docs/examples/coming-from-doctrine.md`): a shop with entities, repositories, cascades, unique keys, queries, full-text search, optimistic locking and transactions, compared with Doctrine; its code runs as a test (`tests/…/Examples`).
- Copying and moving objects between storages (`Transfer\ObjectTransfer`, see `docs/transfer.md`): as stored, keeping UUID, revision, expiration and checksum; optionally with the referenced objects; conflicts in the target fail, are skipped or overwritten; moving deletes only the object itself in the source. Per object results (`TransferResult`). Building blocks: `ObjectStorage::readRaw()`, `writeRaw()` and `delete($uuid, applyChildDeletionPolicy: false)`; `ObjectAlreadyExistsException`. CLI commands `copy` and `move` (UUIDs, `--class` or `--all`, `--to`, `--create`, `--with-references`, `--on-conflict`); in the viewer, **Copy / Move** on a record and for chosen objects, with progress and a retry of failed or skipped objects. `readRaw()` reads as loading does (shared with `load()`), `writeRaw()` writes the files as `store()` does.
- Viewer: a storage that doesn't exist can be created, with a configuration.
- Named configurations (`melia\ObjectStorage\Configuration`, see `docs/configuration.md`): a `Configuration` keeps the lock backend (`LockSettings`: files, semaphores, Redis, Memcached, a database or any symfony/lock connection, with lock lifetime and prefix), the caches (`CacheSettings`: memory, none, APCu, files, Redis, Memcached), the strategy settings and fsync. A `Registry` keeps configurations by unique name, assigns them to storages (`configuration.json` in the storage) and opens storages with them: `$registry->open($directory)` or `$registry->open($directory, 'name')`. `ObjectStorage` takes a `configuration` argument (explicit arguments take precedence) and returns it with `getConfiguration()`; internal storages of search indexes and stepped maintenance use the same locks. `Factory::check()` tests the backends of a configuration. `%env(NAME)%` in settings is replaced by environment variables.
- CLI: commands open the storage with its assigned configuration, or the one named by `--configuration`; `--configurations` (or `$OBJECT_STORAGE_CONFIGURATIONS`) names the directory of the configurations. A storage whose assigned configuration isn't found fails instead of falling back to file locks. New commands `configuration:list`, `configuration:assign` (`--none` to remove), `configuration:check`, `configuration:import` (JSON file or STDIN, `--replace`), `configuration:export` and `configuration:delete`.
- Viewer: managing configurations (create, edit, check, delete) and assigning one to a storage; storages are opened with their assigned configuration. Errors, e.g. an unreachable lock backend, are shown on an error page instead of an empty page.
- Viewer: a consistent layout: every page has a header with the path (breadcrumb), title and actions; contents are on cards. The storage picker suggests storages opened before (kept in the browser), which can be removed.
- Search indexes: the state records the last 20 updates of the documents (`State::$updates`, `State::getLastUpdate()`): completed builds, syncs that changed documents and removals of expired objects, with the time, the number of changed and expired objects and the documents afterwards. The viewer shows the last update in the index list and lists the last updates on the edit and build pages.
- Search indexes: `IndexInterface::getSize()` returns the space an index occupies on disk in bytes (all builds in its directory). The viewer shows the documents and the size (B, KB, MB, …) in the index list, on the edit page and on the build page, where they are updated while building. `File\Directory::size($path)` sums the files of a directory.
- Search indexes: searching a class (`ManagerInterface::search()`, `searchObjects()` with a class name) chooses the index per search, like a database chooses among the indexes of a table: the index must be built and have the fields of the query, `searchOn`, filter, sort and facets; up-to-date indexes come first, for queries those with more searchable fields, then smaller ones. `explain()` returns the plan (`Index\Plan`, `Index\Candidate` with rank and reasons); `NoSuitableIndexException` if no index fits. `Request::$searchOn` limits a query to some searchable fields. Engines implement `EngineInterface::filterAttributes()`. The viewer searches a class from the list of classes and shows the plan.
- `UUID\Helper::createFixedUuidV4($input, $algorithm = 'md5')`: a UUID always the same for the same input, in the format of version 4, e.g. to find an object by a name; used by the search indexes.
- `File\Directory::remove($path)`: removes a directory with all its contents.
- Search indexes (`melia\ObjectStorage\Search`, see `docs/search.md`): full-text search, filters, sorting and facets over the objects of a class, independent of the search engine. `ManagerInterface` and `IndexInterface` define, build, keep up to date and search indexes; `Request` and `Result` describe searches, with filters in the language of the engine; engines implement `Engine\EngineInterface` and `Engine\EngineIndexInterface`. An index is defined by fields with paths into the stored data and declared types (values are converted, so changing stored types don't break the index), built step by step into a new generation while the previous one stays searchable, and kept up to date by `Manager::attach()`. Applications load an index by its name; names are unique per storage across engines, also when several processes create an index at the same time. Definitions and states are objects of an internal object storage (`indexes/internal`), the data of an index lives in `indexes/<engine>/<name>`, pending changes and the UUIDs of a build are UUID tries, one record each.
- Search engine Loupe (`Search\Loupe\LoupeEngine`, optional: `composer require loupe/loupe`, needs `ext-intl` and `ext-pdo_sqlite`): typo-tolerant full-text search on SQLite without a server; accepts Loupe's `SearchParameters` as well.
- `Util\UuidTrie`: a set of UUIDs as a radix trie, stored as one record like any object, with lookups following the digits of a UUID and iteration in ascending order, also starting after a given UUID.
- Search indexes: an explicit sync (`sync()`, **Sync** in the viewer) also removes objects that have expired since they were indexed; `IndexInterface::purgeExpired()` does this alone. Documents have the reserved attribute `expiresAt` (so it can't be a field name), engines implement `EngineIndexInterface::expired()`. Indexes built before have to be rebuilt to find expired objects.
- Viewer: the lifetime of a record can be set (never, in a duration, at a point in time); the page shows the expiration in the time zone of the browser and the time left. Attached search indexes follow lifetime changes (`LIFETIME_CHANGED`).
- Viewer: a record and the page after saving it link to the storage and to the record; leaving a record being edited asks before unsaved changes are lost.
- Viewer: when editing a record, the search indexes of its class to update can be chosen (`ManagerInterface::notifyChanged()` takes the names of the indexes to update and returns the updated ones).
- Linking objects afterwards (`Migration\AttributeToReference`, see `docs/search.md`, "Joins"): turns an attribute holding the UUID of a stored object as text, or a list of them, into references, without reading or writing the referenced objects; UUIDs without an object stay text (`getMissing()`), typed attributes that can't hold an object fail. `apply($object, $uuid)` takes the UUID to store the object under. In the viewer: **Link** on a record (attributes holding UUIDs are listed, or any attribute is set to a reference to a given object) and **Link objects** in the list of a class, linking an attribute of all of its objects with progress.
- Search indexes: fields can be named by their paths in dot notation in filter, sort, facets and `searchOn`, e.g. `friend.friend.name = 'Bob'` for a field with this path (`Index::resolvePaths()`, applied by `search()` and when choosing the index of a class); a path without a field fails with `UnknownPathException`. Engines implement `EngineInterface::renameFilterAttributes()`; Loupe's `filterAttributes()` returns a path as one attribute. Sort criteria may contain dots. In the viewer, the builder takes a field or a path, shows which field a path is, and offers to add a path that isn't indexed to the index (`index-edit` with `addPath`).
- Loupe engine: patterns in filters, which Loupe lacks: `name LIKE 'Ho%'` (`%` any characters, `_` one, `\%` and `\_` literally) and `name CONTAINS 'om'`, also with `NOT`, ignoring case. A pattern is matched against the distinct values of the field (read as facet values) and becomes an `IN` condition; for filterable fields of strings or lists of strings with at most `LoupeEngineIndex::MAX_PATTERN_VALUES` (10,000) distinct values. `filterAttributes()` doesn't report the operators as attributes. In the viewer, the builder offers `CONTAINS`, `NOT CONTAINS`, `STARTS WITH`, `ENDS WITH` (as `LIKE`, with `%` and `_` of the value escaped), `LIKE` and `NOT LIKE`.
- Viewer, query builder: its logic is in `assets/query-builder.js`, tested with Node (`tests/js`: fixed cases and random round trips), its filters by `QueryBuilderFiltersTest` (600 random filters searched with Loupe and compared with an evaluation independent of the engine) and the page with Playwright (`tests/e2e`, `sh tests/e2e/run.sh`). It never changes what is searched: values are written exactly as typed; incomplete or invalid conditions are listed as errors and block searching, using and saving instead of being left out; `BETWEEN` needs the smaller number first; a filter it can't show exactly isn't read but kept (shown above the conditions, removable) instead of "keep the current filter", which could repeat it; sort, facets and *Search on* named by paths are read by their fields, unknown ones kept; groups of only a group and groups combined the same way are written without needless parentheses. The note about a kept filter is hidden when there is none (it was always shown).
- Viewer, query builder: groups of conditions, nested to any depth, each combined with AND or OR and optionally negated (`NOT (…)`); conditions and groups are moved by their handles with drag and drop (pointer events: mouse, pen and touch; Escape cancels), also into other groups. Opening the builder reads the filter of the form back into groups and conditions (a filter it can't show, e.g. a geo filter, is kept and combined); saved queries can be opened in the builder to change them. Saving and searching take changes of the open builder not yet used in the form; a field typed in the form while the builder is open updates only its part of the builder. The loaded saved query is remembered (`saved` in the URL), marked in the menu and suggested as the name when saving, to replace it.
- Viewer, searching: a query **Builder** composing filter (Loupe syntax), sort, facets and the fields searched from the fields of the index; queries can be **Saved** by name in the browser (per storage and index or class) and run again; **PHP** shows the search as code. The syntax help explains filtering by fields joined from referenced objects and by `referencedUuids`, which the field list shows too.
- Viewer: the metadata of a record can be read as stored (**Raw** on the metadata card, with the path of the file).
- Viewer: the objects selected in the list of a class have a menu **Selected** with copy and move to another storage and **Delete** (after a confirmation; the attached indexes follow, objects that can't be deleted are listed with the reason).
- Viewer: managing search indexes (create with suggested fields, edit, rebuild with progress, sync, drop) and searching them with query, filter, sort and facets.
- Child deletion policy (`Strategy\Policy\ChildDeletion`, `Standard::setPolicyChildDeletion()`): `ALWAYS` deletes the objects referenced by a deleted object along with it, recursively; `CALLBACK` decides per reference via `shouldDeleteChild()` of the strategy. The default `NEVER` keeps them, as before.
- Revisions: the metadata of every object holds a revision, incremented with every write of its data; read it with `ObjectStorage::getRevision()`. The context of `OBJECT_SAVED` and `OBJECT_WRITE_FAILED` provides it with `getRevision()` and `getPreviousRevision()`. Objects stored before have the revision `0`.
- Optimistic locking (`Standard::enableOptimisticLocking()`, disabled by default): `store()` throws a `RevisionConflictException` (an `ObjectSavingFailureException`) and dispatches `REVISION_CONFLICT` if the object was stored by someone else since this storage loaded or stored it.
- `SymfonyLockAdapter`: locking based on symfony/lock, usable with any of its stores (Flock, Redis, Memcached, PDO, Semaphore, …). Stores like Redis keep no lock files and free locks of crashed processes after a TTL.

### Changed
- Public API and internals are separated: the classes of the OQL engine (`Query\Ast\*`, `Lexer`, `Parser`, `Planner`, `Plan`, `Executor`, `Writer`, `WritePlan`, `Access`, `AccessChoice`, `Printer`, `Token`, `Values`), `Search\Loupe\FilterNegation`, `Search\Loupe\FilterNumbers`, `Util\Maintenance\SteppedMaintenance` and `Util\Maintenance\TaskState` are marked `@internal` and not covered by the backward compatibility promise. `Query\Oql`, `Query\Result`, `Query\Reference` and `Query\Exception\QueryException` are marked `@experimental`, as are the CLI command `query` and the query console of the viewer.
- `composer.json` requires `php` `^8.5` (before `>=8.5`).
- Dependencies updated: Symfony 8 (`symfony/console`, `symfony/cache`, `symfony/lock` `^8.0`, before `^6`); for development PHPUnit 13 (before 10), Monolog 3, PHPStan 2.3 and Twig 3.30. The CLI commands are named with the attribute `#[AsCommand]` (Symfony removed `$defaultName`); the tests use PHPUnit attributes (`#[DataProvider]`, `#[RunInSeparateProcess]`) and stubs where no expectations are set.
- The viewer exports the reference graph of a record with the new `Graph\Export\Dot\DotExporter` (Graphviz DOT, dangling references in red); `sebastian/object-graph` is no longer needed, it doesn't install alongside PHPUnit 12 or newer.
- `ObjectStorage` is grouped in sections, and its protected methods are named by one convention (see `docs/internals.md`): `load`/`store`/`delete` for objects, `read…`/`write…` for files, `hydrate…`/`serialize…` for converting. Renamed: `loadFromStorage()` → `loadFromFiles()`, `buildLoadedObject()` → `hydrateObject()`, `processLoadedData()` → `hydrateProperties()`, `processLoadedArray()` → `hydrateArray()`, `serializeAndStore()` → `storeObject()`, `createGraphAndStoreReferencedChildren()` → `serializeGraph()`, `saveMetadata()` → `writeMetadata()`; `readObjectFiles()` reads the files of an object for `load()` and `readRaw()`. `readFile()`, `loadFromJsonFile()`, `decodeJson()` and `serializeMetadata()` are replaced by the new classes `File\JsonFileReader` and `File\JsonFileWriter` (`getJsonFileReader()`, `getJsonFileWriter()`), also used for the assignments of configurations; the unused `$validator` of `loadFromJsonFile()` is gone. Subclasses overriding the old names have to rename them. The public API is unchanged.
- Search indexes read objects with `ObjectStorage::readRaw()`, under their lock, with checksums verified and interrupted writes completed, instead of reading the files on their own.
- `maintenance:rebuild-stubs`, `ObjectStorage::rebuildStubs()` and the viewer rebuild the class index in place and step by step (`Util\Maintenance\StubRebuilder`), with progress (stubs created, removed, corrupted objects): missing stubs are created, wrong ones removed, and the registry of class names is rebuilt from the stubs (`ObjectStorage::rebuildClassnameRegistry()`). The index stays usable meanwhile; the CLI no longer switches safe mode on and off. `rebuildStubs()` takes a progress callback and returns the progress.
- `ShardRebuilder` and `StubRebuilder` share the base class `Util\Maintenance\SteppedMaintenance`: the state (`TaskState`) and the snapshots (UUID tries) of a task are objects of an internal object storage in `<storage dir>/maintenance/internal`, one record each, and steps are serialized by its lock; `ObjectStorage::markAsCorrupted()`, `getStubDirectory()` and `getClassStubDirectory()` are public.
- `maintenance:rebuild-shards` and the viewer show the progress of a shard rebuild (objects processed, files moved, estimated remaining time). `ShardRebuilder` moves the files of the objects step by step (`start()`, `step()`, `rebuildShards()` with a progress callback); an interrupted rebuild is continued by the next run, with the depth it was started with, and keeps the storage in safe mode until then.
- **Breaking:** `StrategyInterface` has new methods `getPolicyChildDeletion()`, `shouldDeleteChild()` and `optimisticLockingEnabled()`. Strategies extending `Standard` get them; custom implementations have to implement them.
- The metadata format version (`Metadata::VERSION`) is now `2` (field `revision` added) and is written from the constant instead of a fixed `1`. Older metadata is still read; no migration is needed.
- The default lock adapter is now `SymfonyLockAdapter` with file locks in `<storage dir>/locks` (previously `<uuid>.lock` files directly in the storage directory). The CLI uses the same location.
- New dependency: `symfony/lock`.
- Stores are crash-safe: data and metadata are written as a group by the writer (as pending files `<uuid>.obj.pending`, `<uuid>.metadata.pending` first, then committed by atomic renames, the data before the metadata). A store interrupted between both commits is completed when loading or deleting the object, instead of enabling safe mode.
- **Breaking:** `ObjectStorage::buildShardedDirectory()` only builds the path and no longer creates the directory; the writer creates it when the first file is written. Looking up unknown UUIDs (`exists()`, `load()`, `loadMetadata()`) no longer leaves empty shard directories behind. Code writing into shard directories itself has to create them.
- `Writer` always creates a missing directory when writing; the parameter `$createDirectoryIfNotExist` of `Writer::atomicWrite()` has been removed (passing it has no effect anymore).
- `Writer` flushes every written file and the rename of it to disk (`fsync`). This makes stores considerably slower; disable it with `$storage->getWriter()->setSyncEnabled(false)` (or `new Writer(sync: false)`) where durability doesn't matter.
- The default writer and reader of a storage are created once and kept, so their configuration applies to later operations (previously `getWriter()`/`getReader()` returned a new instance on every call).
- **Breaking:** `WriterInterface` has new methods `atomicWriteAll()` (writes several files as a group) and `recover()` (completes an interrupted group write), used for the crash-safe store, as well as `syncEnabled()` and `setSyncEnabled()`. Custom writer implementations have to implement them (see `Writer`). `createEmptyFile()` has been removed from `WriterInterface` and `Writer`; the storage creates its index files through the IO adapter.
- **Breaking:** `AdapterInterface` has new methods `fsyncFile()`, `fsyncDirectory()`, `renameSync()` and `moveFileSync()`, used to flush files, directories, renames and moves to disk. Custom IO adapters have to implement them (see `RealAdapter`).
- Safe mode only blocks modifications: loading, listing and matching objects keep working, only exclusive locks (store, delete, lifetime changes, exclusive loads) are rejected. Previously every lock was rejected, so a single corrupted object made the whole storage unreadable. Loads no longer check the safe mode file, which saves a file lookup per load.

### Removed
- `Locking\Backends\FileSystem`, use `SymfonyLockAdapter::createFileLockAdapter()` instead. It deleted lock files on release, which allowed two processes to hold the same lock at once.
- `Locking\Backends\CachedLockAdapter`, use `SymfonyLockAdapter` with e.g. `RedisStore` or `MemcachedStore` instead. PSR-16 has no atomic "add", so two processes could acquire the same exclusive lock at once; with its default prefix `lock:` it didn't work with `Psr16Cache` at all. There is no replacement for APCu-based locking, since symfony/lock has no APCu store.

### Important Note
- **Stop all processes using the old version before upgrading.** Old and new versions lock different files, so they don't exclude each other while running side by side.
- Old `<uuid>.lock` files in the storage directory are no longer used and can be deleted once no process of the old version runs.
- Code creating `FileSystem` or `CachedLockAdapter` explicitly has to be migrated to `SymfonyLockAdapter`, see "Lock backends" in the Readme.

### Fixed
- Upgrade test (`Upgrade\UpgradeFrom0010Test`): a storage written by 0.0.10 (`tests/fixtures/upgrade/storage-0.0.10`, made by `generate-0.0.10.php` with the code of that version) is opened with this version: classes, values, chains, lists and cycles of references, `__unserialize()` with references, expirations, deleted objects, writing (metadata upgraded to version 2), stub rebuild, unique indexes and OQL.
- `Transaction::getStorage()` could return a storage that isn't an `ObjectStorage` despite its declared type, and the transaction log was written with the removed third argument of `Writer::atomicWrite()`. PHPStan (level 3, now configured in `phpstan.neon`) reports no errors for `src` and `tests`.
- Loupe engine, found by the tests of the query builder (all in loupe/loupe 1.1):
  - Filters with negative numbers failed (`price > -1`, `IN (-1)`, `BETWEEN -5 AND 5`); they are written as strings, which Loupe compares as numbers (`Loupe\FilterNumbers`).
  - `BETWEEN` with bounds in the wrong order (`BETWEEN 5 AND 1`) found the range between them; it is searched as comparisons, as in SQL, and finds nothing.
  - After a filter Loupe failed on inside parentheses, every following filter of the same index failed ("Expected a closing parenthesis"), in long-running processes until the end; the parser of Loupe is reset after a failure.
  - `NOT` of comparisons and `BETWEEN` missed documents without a value (`NOT (age > 1)` didn't find those without an age); they are included now, so `NOT` is always the complement.
  - `LIKE` and `CONTAINS` missed values with a comma (Loupe's facets split them) and the empty string (`LIKE '%'`); the values are read from the documents.
- Loupe engine: `NOT` before a condition or a group, which Loupe doesn't support (it rejected it at the start of a filter and silently ignored it after `AND` or `OR`, returning wrong hits), is rewritten into the negated conditions following De Morgan's laws (`Loupe\FilterNegation`): `NOT (a = 1 OR b IN ('x'))` becomes `a != 1 AND b NOT IN ('x')`, `NOT (x BETWEEN 1 AND 2)` becomes `(x < 1 OR x > 2)`; the geo filters can't be negated.
- Metadata naming no UUID (written by older versions) or another one (duplicates made by older versions of the viewer copied the metadata of the original) gets the UUID from the file name when loaded, so writing it (e.g. setting the lifetime) no longer overwrites the metadata of the original, and copying or moving the object works. A corrected UUID is logged.
- CLI `delete --force` passed its flag to `ObjectStorage::delete()`, which ignored it; it now calls `delete($uuid)`, as the second argument decides whether the child deletion policy applies.
- `rebuildStubs()` lost the class index instead of repairing it: it removed the stub directory, after which the stubs couldn't be created again in the same process (the removed directories still counted as existing), and the list of classes wasn't written again, so other processes saw no classes. `Directory::tearDown()` now forgets the removed subdirectories as well (`Registry::markTreeAsNotVerified()`), and the class index is rebuilt in place.
- Viewer: the storage links of the record, class and UUID pages pointed to a storage named "storage" instead of the current one.
- `Directory::tearDown()` removed directories with `rm -rf` in a shell, which fails on Windows without an `rm` in the path. It removes them in PHP now, and returns false if something couldn't be removed.
- The maximum depth of a stored object graph (512 by default) limited the number of arrays and referenced objects in it instead of its depth, as the level was never decreased: an object with a list of more than 512 arrays couldn't be stored.
- `ShardRebuilder` disabled safe mode after a rebuild even if it had been enabled before (e.g. because of a corrupted object), and also after a failed rebuild, which leaves files in directories of different depths.
- `setLifetime()` / `setExpiration()` wrote back cached metadata, which may be outdated if another process stored the object in the meantime; its checksum then no longer matched the data. The metadata is now read from disk under the lock.
- `store()` didn't lock the referenced objects it wrote along with the stored object. Two processes writing the same referenced object at once could commit each other's pending files, and one of the stores failed. Each referenced object is now locked exclusively while its files are written.
- Several processes creating the same directory at once (shard or lock directory) could fail or emit `mkdir(): File exists` warnings.
- `__serialize()` returning int keys (e.g. `ArrayObject`) failed with an `UnsupportedTypeException`.
- **Breaking:** `__unserialize()` received the internal references (`['__reference' => '<uuid>']`) instead of the objects returned by `__serialize()`. The referenced objects are now loaded and passed as objects (`null` if deleted); reference cycles get the instance being restored. Code evaluating the reference arrays itself has to be adapted.
- `PropertyHydrationFailureException` was created with `null` as code, which is deprecated.
- PHPUnit configuration migrated to the PHPUnit 10 schema; data providers are static.
- Processes registering new classes at the same time overwrote each other's entries in the class name registry (`classnames.json`), so `getClassNames()` missed classes. The registry is now updated under a lock and re-read before writing.
- Tests running several processes on one storage at once (group `concurrency`, excluded with `--exclude-group concurrency`): shared referenced objects, exclusive read-modify-write, reads during writes and class registration.
- Loading a UUID under which nothing is stored (never stored or deleted) enabled safe mode for the whole storage and threw an exception. `load()` now returns `null` in this case; safe mode is only enabled for data without metadata. Missing metadata is no longer logged or reported as `IO_READ_FAILURE` / `METADATA_LOADING_FAILURE` either.
- `ObjectPersistenceContext::getPreviousObject()` of the `OBJECT_SAVED` event returned the object being stored itself, taken from the cache, instead of its previous state. It now returns the previously stored state, read from disk before the data file is overwritten and without replacing the cached object.
- An exclusive load (`load($uuid, true)`) returned the cached object if the process had one, which doesn't know about changes of other processes. A read-modify-write in a long-running process could therefore lose updates. An exclusive load now always reads the stored state and replaces the cached copy.
- The default writer and reader of a storage ignored the IO adapter given to the storage and always accessed the real filesystem. They now use the adapter of the storage, and follow it when it is changed by `setIOAdapter()`; an explicitly set writer or reader keeps its own adapter.
- Viewer: duplicating a record copied the metadata including the UUID of the original, so later metadata updates of the duplicate (e.g. its lifetime) overwrote the metadata of the original. The duplicate is now written with its own UUID, data and metadata as a crash-safe group.
- Loading an object that another process had updated in the meantime could enable safe mode for the whole storage: the data was validated against outdated cached metadata. On a checksum mismatch the metadata is now reloaded from disk once; safe mode is only enabled if the data doesn't match the metadata on disk either.
- `load()` no longer releases a lock that the caller acquired before (e.g. by a previous exclusive load or a running `store()`).
- `store()` of a loaded `LazyLoadReference` failed for objects not implementing the UUID `AwareInterface`.
- `BEFORE_UPDATE` / `AFTER_UPDATE` were not dispatched when updating an object without passing its UUID explicitly.
- Scalar type conversion during hydration never took effect. Values are now converted to the declared scalar type, and lossy conversions (e.g. `"abc"` or `2.5` to `int`) throw a `TypeConversionFailureException`.
- `LazyLoadReference` kept the first loaded reference and its root object alive for the lifetime of the process. Expired references are now reported as expired instead of "could not be loaded".
